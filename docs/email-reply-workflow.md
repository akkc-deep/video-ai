# 通过回复 QQ 邮件继续制作

`generate_video.cmd` 默认使用邮件续作流程。图片仍按场景参考依赖分批生成，
每批用一封邮件发送全部候选预览图及回复模板；原图继续保存在任务目录。
这不会更改旁白、字幕去标点设置、已接受的图片或冻结配方。

## 一次配置

在 QQ 邮箱网页设置中启用 **IMAP/SMTP 服务**，将授权码保存到源码目录
`config/secrets.local.json` 的 `VIDEO_AI_SMTP_AUTH_CODE`。SMTP 发信和 IMAP
收信共用它；环境变量仍可临时覆盖。本地凭据文件已被 Git 忽略。

参考图阶段会在任务缺少参考能力/存储配置时自动读取已有的
`config/reference.local.json`，通过正式补充配置入口绑定到任务；已绑定的参考
设置和冻结配置不会被替换。也可通过 `mail-video --reference-settings PATH`
显式指定补充文件。该参数只用于生成续作，不混入选图或观看回复的提交。

程序通过 `imap.qq.com:993` 的 TLS 连接只读查找当前制作邮件的回复，
不移动、删除邮件，也不改变已读状态。

## 制作和回复

新视频的命令不变：

```powershell
& "E:\code\py\video-ai\generate_video.cmd" -Script "E:\VideoAI\shared\assets\文案.txt" -Title "视频标题"
```

恢复已有视频：

```powershell
& "E:\code\py\video-ai\generate_video.cmd" -Video 0003
```

请保持电脑及制作窗口运行。显示“正在等待邮件回复”时，无需再输入命令。
直接回复当前邮件，在正文中填写模板，例如：

```text
确认=提交
scene_0002=request_02_image_01
scene_0003=request_01_image_01.png
```

每个场景恰选一张，编号来自当前批次；`.png` 后缀可省略。程序会记录选择并
自动生成下一批。回复缺项或格式有误时，会发一封补填说明，继续等待。
邮件正文中的引用、未填写模板、旧批次回复和重复回复不用于推进新批次。

全部图片选完后，程序再通过邮件收集整组图片一致性确认。片段观看、连续性
检查及成片确认同样附有当前材料和 JSON 回复模板，只需填写本人实际观察的
字段并回复；身份和来源字段由程序保留。选择图片不等于通过观看审核，
`failed/unverified` 判断不会被转换为 `passed`。发布另需明确回复同意发布。

较大的视频超过普通邮件附件上限时，邮件列出完整本地文件路径。请打开该
文件完整观看、核对旁白和字幕后，再按模板回复。图片批次使用可查看的预览
副本；如最小预览仍超过限制，程序会明确停止，不漏发场景。

## 暂停、恢复与异常

Ctrl+C 可以暂停邮件等待。再次使用同一视频编号启动，会恢复当前邮件线程，
不会因轮询或重启而重新生成已接受的素材。网络短暂中断会自动重连；
凭据或 IMAP 服务未就绪时，会保留进度并说明设置要求。

本地日志位于该修订的 `production/mail-workflow/`。程序保留待确认请求、
实际回复和提交结果。SMTP 已开始发送但结果未知时，不会自动重发；需先核对
原邮件。切换到新修订后，旧修订的邮件回复不会发布新修订。

原来的单次制作接口仍可直接使用：

```powershell
& "E:\code\py\video-ai\scripts\start_windows.ps1" make-video --video 0003
```

该接口推进一次后退出，不负责持续监听邮件。`mail-video --once` 则用于推进并
查询一次当前回复后退出。持续自动续作使用默认的 `generate_video.cmd`。
