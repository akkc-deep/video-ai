## Critical / Important findings

No Critical findings. Three Important findings remain in the reviewed version:

1. **Expired whole deadline prevents recovery of an already persisted successful original result.** `src/video_ai/runtime/scene_comfy_transactions.py:366` raises before the existing HTTP rows are reconciled. The earlier `validate_scene_submission()` shortcut requires `submission.json`; it cannot recover a missing marker. Reproduction: persist the original successful history response and owned output, interrupt immediately before writing `submission.json`, then resume after `intent.created_at + wan_timeout`. All original success evidence is present, but the run is permanently refused before `_history_candidates()` can reconstruct the result. This violates the specified local recovery at durable boundaries; it is distinct from extending the inference/tracking deadline. Move the expired-deadline refusal to the boundary requiring service/network tracking, after attempting guarded, conflict-checked recovery from persisted rows and output. Keep the original deadline and reject every expired path needing GET/service or unresolved work. Add a missing-submission-marker, expired-clock test that proves zero new POST and zero service/GET; the existing completed replay test only covers an existing submission marker.

2. **Explicit-mode revision preparation requires semantic inputs even when the revision invalidates them.** `src/video_ai/runtime/production_scene_revision.py:424` unconditionally enters target-budget creation for an explicit mode, and `:430` immediately loads target common inputs. A valid reconfigure changing font, voice, or planning configuration marks `common:all` and downstream plan dirty (`src/video_ai/planning/scene_revision.py:290`), so those nodes are not imported. The newly frozen target has no units/timeline/committed plan yet. `load_scene_common_prefix()` falls through to `load_prepared_inputs()`, which refuses missing reports, leaving revision preparation failed after writing its options/commit. This affects explicit segmented as well as whole. Create the early target budget only when common and committed semantic plan inputs are actually available/proven; otherwise let the ordinary held-lock source writer derive it after regeneration. Preserve strict refusal when downstream video records already exist without a budget. Add a reconfigure test that invalidates common inputs and still reaches `revision_ready` without a budget or model call, then verify later derivation uses the new semantic inputs.

3. **A complete pre-rename budget temporary blocks every subsequent invocation.** `src/video_ai/runtime/scene_execution_records.py:253` refuses any `execution-budget.*.tmp` whose token differs from the current lock. `RunLock` allocates a new token for every new instance, including after exception cleanup or legitimate dead-owner reclamation. Reproduction: interrupt after the complete budget temporary is fsynced but before rename; release/reclaim the old lock and rerun with a new lock. The exact valid temporary remains, and the writer refuses indefinitely. `test_owned_exact_temporary_recovers_after_rename_interruption` retries inside the same held lock, so it does not cover process/invocation restart. Under a valid new run lock, after admission and downstream-absence checks, validate all leftover temporary paths and complete contents against the exact newly derived budget; preserve the old files and create/promote only the new owner's temporary. Reject malformed, different or redirected leftovers and never reclaim a live owner. Add a new-lock restart test as well as continued invalid-leftover refusal tests.

## Spec-compliance verdict

**Changes required for recovery/revision compliance.** The inspected main integration otherwise follows the design:

- The absent/old visual branches keep legacy inputs/complete schemas; explicit modes select persisted execution and schema3 inputs/complete. Semantic plan identities remain based on the original plan. Whole prompt binding uses pure execution clips, without a future budget/rendering SHA cycle.
- Admission pins the real original assessment, raw resource/HTTP inventories, case/prepared identities, native frames, original feedback, graph, archived software and current inference environment. Frozen aliases require matching closure content. Archived product code is data; the changed product implementation is not asserted equal to old VCO-05 code.
- Source stores enumerate execution clips; native mappings, complete indices, upscale rows, composition, observations and delivery consume that validated closure. Whole rows have no parent chain. Existing source/final observation gates and current continuity admission remain required.
- Revision source enumeration, ancestry, dependency construction and invalidation use the source execution. Mode changes invalidate same-name clip/video observation nodes. Imported semantic inputs and choices remain separate from target execution derivation.
- Read-only execution loading refuses missing budgets without creating them. Budget creation checks the held run owner, downstream absence, exact reconstruction, fsync and rename. Source/media writers retain execution-budget and whole-evidence checks through their guards.
- Explicit writer decorators are conditional; historical paths are not wrapped in the new writer scope. Whole admission memo hits invoke the full evidence guard, including artifact hashes, inventories and attached environment/frozen guards. Memo dictionaries are invocation/session-local; Windows protected hashes retain mandatory read handles, and unprotected files are hashed again.
- Original intent recovery remains GET-only and does not allocate a second POST. Whole failures stop subsequent scenes; owned whole service sessions add GPU lease/resource sampling and cleanup through nested `finally` blocks. Existing completed delivery replay validates the original publication instead of publishing again. The expired missing-marker exception above remains unresolved.

## Code-quality verdict

**Generally coherent separation, but not ready to approve until the three Important findings are fixed and verified.** The execution layer avoids rewriting semantic inputs, strict schemas expose mismatches, and existing transaction/media primitives carry most behavior. Recovery tests should cover raw-evidence-to-index boundaries and genuinely new lock owners, not only fully committed replay or retries within one held lock. Revision preparation must respect the existing distinction between inherited and newly regenerated common inputs.
