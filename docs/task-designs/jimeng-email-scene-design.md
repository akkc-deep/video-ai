# 即梦起始图、邮件选图与段落分镜设计

日期：2026-10-18。状态：用户已确认包含画面一致性要求的总体方案，并要求据此拆分任务；尚未修改生产代码或调用收费接口。

任务身份、执行顺序和状态以 [jimeng-scenes 任务板](../task-handoffs/jimeng-scenes-task-board.md) 为准。本文是总体方案，不代替各任务实施前的具体设计。

## Goal

- 输入仍为完整文案；保留完整原文配音和字幕。
- 按段落内容归纳少量关键画面，允许一个画面覆盖多句旁白。
- 起始图通过火山引擎官方即梦图片 API 生成。
- 用户可以自行设置文生图模型及其参数，不固定某个模型版本。
- 候选图发送到 `318575094@qq.com`；用户已确认同一邮箱作为发件与收件邮箱。
- 用户选择图片后，继续现有 Wan 图生视频、超分、配音字幕合成和交付。
- 起始图之间、起始图到动态视频、相邻连续片段及最终成片都需要保持画面一致性。

一致性具体包括同一主体的身份、外形结构、颜色和服装，场景空间关系、时间与光照，以及全片视觉风格。景别和视角可以改变；原文明示的换景、换装、时间变化必须保留，并记录有依据的变化。

## Scope

本设计将“提交所选编号”解释为用户在当前对话告知编号，或提供本地选择文件，再显式续作。邮件自动收信、解析回信、邮件内在线选图页面不在首版范围内。
包含共享视觉设定、基准图选择、参考图约束、同场景动态续接和整组画面/连续视频的一致性验收。参考图属于此次一致性要求下新增的设计范围，不改变用户自行设置文生图模型的要求。

## Approach

### 现状与改动原因

`production.py` 依次执行分段、配音、时间轴、分镜、起始图、动态视频、超分、合成与交付。
`production_timing.py` 和 `storyboard.py` 从配音单元生成固定槽位，并将较长槽位细分。
现有校验还限制跨主单元的有效语音重叠，因此不能只通过修改提示词实现多句共用画面。

`production_visuals.py` 的起始图路径固定为 SDXL/ComfyUI；图片报告、请求记录、预检和已完成前缀校验也绑定了该服务。
`adapters/common.py` 的 HTTP 客户端仅允许本机 HTTP，不能直接用来发送外部 HTTPS 请求。
现有实际看图审核机制可以提供图片身份绑定思路，但“邮件发送成功”不能代替用户选图。

### 方案选择

推荐在现有自动制作入口内增加版本化策略 `paragraph_jimeng_v1`：新策略使用段落画面、即梦候选图和选图等待状态；旧运行继续沿用其冻结策略。

另一种方案是先写独立的即梦出图与发邮件脚本，再手工导入旧分镜。接入较快，但无法解决配音与分镜的强绑定，且容易重复发送和丢失选图关联。
全面替换旧生产链会扩大历史运行恢复风险。首版采用版本化增量接入，复用现有配音及视频处理能力。

### 内容与时间轴

定义三类独立对象：

| 对象 | 作用 | 与原文的关系 |
| --- | --- | --- |
| narration unit | 配音和字幕的无损文本单元 | 保留所有原文范围及顺序 |
| scene | 需要用户选一张起始图的关键画面 | 可关联多个连续旁白单元 |
| clip | 一次 Wan 请求对应的动态片段 | 覆盖某个画面的部分或全部时长 |

保留现有语音单元细分，不再以其边界强制切镜头。新增画面规划器读取完整原文、段落边界、上下文和配音时间轴，输出有顺序的场景及图片、动作描述。
画面摘要只用于视觉规划，不能替换配音或字幕原文。画面切换跟随主题、场景和动作变化，不要求将每句话逐字画出来。
同一实体的外观从原文和共享视觉设定提取，不添加题材专用硬编码。

画面通过连续的 `unit_ids` 和原文范围关联旁白；首版仅在旁白单元边界切换画面，不推断单元内部的词级时刻。
所有画面的有效时间区间必须无重叠、无空洞地覆盖完整时间轴，包括开头、停顿和结尾。

画面数由语义归纳决定，允许配置每段的目标画面数（默认 3，可为更短段落减少），不因句号数量自动增加图片。
视频规划设置单请求 `max_clip_seconds`，首版默认 6 秒。长画面可拆为多个串行动态片段，首片使用用户选定的起始图，续片使用上一片实际保留末帧作为输入，具体规则见下文。
有意切换角度或场景时使用相应的新画面起始图，并在画面计划标为剪辑切换，不能将独立重启动作冒充同一连续镜头。不得通过循环、冻结、慢放或截断旁白来掩盖时长不足。
用户减少图片数量不会被解释为压缩完整原文或取消必要的动态片段。

### 一致性设定与参考图

新增 `production/visual-bible.json`，记录全片风格、每个重复主体的 `entity_id`、有原文依据的固定属性、用户选定的视觉属性，以及场景组的环境、光照、时间和空间关系。
原文事实与画面创作选择分别保存；未明确的颜色或服装可以由用户选中的基准图确定，但不能标为原文事实。共享设定摘要写入所有相关图片和视频请求。
相邻画面只变化当前镜头所需的视角、构图和动作，不能每次重新自由描述主体身份。固定随机种子只用于复现请求，不能作为一致性已达标的依据。

采用先选基准、再生成关联画面的顺序：

1. 规划重复主体和场景组，标出每组最先出现的实际画面作为基准，不额外强制生成角色设定图。
2. 先生成基准画面的候选并发邮件；用户选定后冻结图片 SHA256 和视觉设定版本。
3. 后续有关画面同时使用已选基准图和固定视觉设定；多主体画面显式标注每张参考图约束的主体或背景。参考关系构成有向无环图，按依赖顺序分批生成和选图。
4. 每个画面直接引用不可变的基准，必要时再附相邻已选画面；不能仅引用上一张生成图而让外观误差逐步累积。每次请求的参考图数由所选模型能力限制，超限时先返回配置/规划错误，不静默漏掉主体。

邮件同时附基准图、候选图及所需保持的属性，生成整组对照图供选图者比较；对照图仅用于查看，不能作为 Wan 起始图。
用户可以选择候选，也可以指出某画面不一致并要求重做；显式重做仅影响该画面和依赖它的后续画面。重做保留旧候选及失败观察，重选基准需要新修订的运行，不能修改已接受的历史。

模型仍由用户配置：若 `image_generation.req_key` 支持参考图，后续画面继续使用它；若只支持纯文生图，则使用用户显式配置的 `reference_generation.req_key` 与独立参数。程序不得自行更换模型。
参考图能力来自已核对的模型配置档，包含输入字段、数量和尺寸限制；未知模型先验证能力，不因模型名称相似而推定支持。
缺少参考图能力或关联模型配置时，返回 `awaiting_image_model_configuration`，在付费生成关联画面前停止；不能无提示退回全部独立文生图。

对仅接收图片 URL 的配置档，首版提供 TOS 参考图发布模块：把用户选定原图按 `run_id/sha256` 存到配置的私有桶，签发有限时效的 HTTPS GET URL，再提交为 `image_urls`。
桶名、地域、endpoint 和凭证环境变量名由本地 `reference_storage` 配置提供；不创建桶、不更改桶访问策略。缺失配置时停止并保留基准选择。
URL 的有效期必须覆盖单任务最长等待时间和下载余量；超出服务允许的签名期限则拒绝该超时配置。任务完成前不删除对象，URL 不写入邮件或普通日志。
恢复时核验本地 SHA256 与对象来源；未提交的意图可以重新签发 URL，已受理任务只能查询原任务，不能因 URL 刷新重发生成请求。该服务组合是否可实际取图必须在真实验收中验证。

### 动态视频的延续与验收

同一连续画面的片段组成 `parent_clip_id` 链，严格串行生成。记录 `scene_id`、基准图、视觉设定摘要、直接输入图片身份和父片身份，视频提示词保留主体及环境的不变项。
续片取父片实际参与成片的最后一个原生帧，不能取 Wan 生成但被裁掉的尾部补齐帧。末帧先保存并记录原视频 SHA256、源帧索引和 PNG SHA256，再作为续片起始图。
续片额外规划一个衔接帧，并在最终映射中丢弃其首帧；每个后续保留帧及旁白区间重新核算，最终帧数仍与时间轴一致。不能直接拼接全部模型输出而产生重复边界或时长增长。

新增一致性观察记录，包含 `scope`、基准/画面/片段 ID 与 SHA256、观察者、实际看图或播放范围、各不变项判断、具体问题、`passed/failed/unverified` 结论。
检查分为三个范围：整组起始图与基准、每段连续视频与其起始图、同场景衔接及最终成片。仅检查首尾静帧不能证明动态过程中没有变形。
用户选图时明确确认整组主体与风格是否一致；单独选中图片编号不自动代写整组一致性通过。实际观察由用户或具备查看能力的审查者提供，不增加未经配置的视觉模型调用。
续片前必须核实父片主体、过程和末帧没有漂移；没有有效观察时保存父片并返回 `awaiting_continuity_review`。独立场景不因另一条连续链等待而被判为失败。
最终成片必须实际连续观看并核对以上各项；失败或未核实均不能自动正式交付。允许保留带未验收状态的候选片供检查，不把技术编码通过当成一致性通过。

一致性问题采取有边界的返工：图片问题显式重做对应画面；片段漂移显式重做问题片段及其依赖续片。相关选择、观察和下游媒体身份随修订失效；已确认无关的基准和片段可在新修订运行中复用，不无限自动重试。

### 即梦官方接口与模型配置

采用智能视觉官方异步接口族，而非将方舟 API Key 当作 AK/SK 使用：

- HTTPS 服务：`visual.volcengineapi.com`。
- 采用官方签名方式，凭证为 AK/SK；签名地域 `cn-north-1`，服务 `cv`。
- 提交和查询分别使用 `CVSync2AsyncSubmitTask`、`CVSync2AsyncGetResult`，接口版本 `2022-08-31`。
- 模型标识放在配置项 `req_key` 中，提交和查询都使用冻结的实际值。

用户配置示意（文档示例，尚不是已实现的配置文件）：

```json
{
  "production_strategy": "paragraph_jimeng_v1",
  "image_generation": {
    "provider": "volcengine_jimeng",
    "req_key": "jimeng_t2i_v40",
    "access_key_env": "VIDEO_AI_VOLC_ACCESS_KEY",
    "secret_key_env": "VIDEO_AI_VOLC_SECRET_KEY",
    "model_parameters": {
      "width": 2560,
      "height": 1440,
      "force_single": true
    },
    "candidates_per_scene": 2
  },
  "scene_planning": {
    "target_scenes_per_paragraph": 3,
    "max_clip_seconds": 6
  },
  "selection_email": {
    "sender": "318575094@qq.com",
    "recipient": "318575094@qq.com",
    "smtp_host": "smtp.qq.com",
    "smtp_port": 465,
    "smtp_security": "ssl",
    "smtp_password_env": "VIDEO_AI_SMTP_AUTH_CODE"
  }
}
```

模型标识是用户输入，不限制为上例。官方文档中的例子包括 `jimeng_t2i_v30`、`jimeng_t2i_v31`、`jimeng_t2i_v40` 和 `jimeng_seedream46_cvtob`。
参数按所选模型配置，不能将 4.0 的 `force_single` 等字段强制发送给全部模型。提供已核对模型的参数预设；对于同一异步协议下的其他模型，允许显式设置 `req_key` 和参数，保留实际请求及服务端错误，不宣称自动兼容新协议。
`model_parameters` 不得覆盖程序管理的 `req_key`、`prompt`、参考图片、任务 ID 和鉴权字段。批次数量是程序规划参数，不臆造官方通用 `n` 参数。
CLI 增加 `--image-model REQ_KEY` 覆盖配置；只作用于新运行。恢复原运行必须使用冻结模型及参数，变更模型需要新运行。

不同模型的图片尺寸约束不同。不能把当前 SDXL 的 1280×720 固定校验套到所有即梦图片上。
图片生成保留官方原图；选定后生成比例适配的 PNG 副本供 Wan 使用，记录原图和副本的身份及适配规则。
首版要求配置和实际结果为横向 16:9；对比例不符的候选报错，不静默裁掉主体或拉伸图片。

新增独立外部 HTTPS 客户端；复用既有日志和异常分类的思路，不放宽所有本机服务的地址限制。
每次提交先保存不含凭证的请求意图，成功后立即保存 `task_id` 和服务端 `request_id`。
先检查业务 `code`，再读取 `data` 和任务状态；分别处理排队、生成中、完成、失败、找不到和过期。
查询与图片下载采用有限期限、退避和中断恢复；已有任务 ID 时只查询原任务。提交结果不明时停止，不能以轮询或重试为名重复付费提交。
生成完成后立刻下载原始图片，避免把有有效期的服务端 URL 当作长期素材或唯一邮件内容。
凭证、Authorization 头及带签名下载 URL 不写入普通日志、邮件或冻结配置；诊断中保留请求 ID 和脱敏字段。

### 候选图、邮件和等待状态

每个画面默认发起 2 个候选请求，同一轮共享已冻结基准和视觉设定，记录画面 ID、候选 ID、模型、参考图身份、提示词、实际输出和 SHA256。基准未选定前不能提交其依赖画面的请求。
若模型单次返回多图，全部保存并赋予唯一候选编号；不将多张输出拼成一张 Wan 输入。已知支持强制单图的预设优先显式设置该参数。
生成失败保留已有候选和请求记录；不自动无限补图。明确失败可显式重试，提交结果不明必须先核对。

邮件采用 SMTP，正文提供运行编号、每个画面摘要、对应原文、候选编号和选图说明，附带实际候选图。
邮件中的编号应能直接复制，例如 `scene_0001=candidate_02`。支持内嵌预览，完整图片作为附件；不只发送临时远程链接。
按实际 MIME 编码后大小拆分邮件，配置默认上限为每封 15 MiB；每封保留批次编号和页码，单图超限时只缩小邮件副本，原图仍本地保存。
发送前保存完整邮件及稳定 Message-ID，确认 SMTP 接受后保存回执。SMTP 接受不表示邮件已进入收件箱。
没有发送回执但存在发送意图时，状态为 `email_delivery_unknown`；普通续作不自动再次发送，显式重发会产生新的邮件尝试记录。
缺失 SMTP 授权码、发送失败或部分邮件未确认时保留候选，修复配置后继续，不重新出图。
QQ SMTP 使用授权码，通过环境变量读取；具体账号是否启用 SMTP、授权码是否有效由实际连接验证。

新策略的起始图阶段按依赖批次执行三个子步骤：`candidates`、`notification`、`selection`。基准批次或后续画面批次生成和邮件发送完成后返回 `awaiting_image_selection`，不当作模型失败。
等待时释放运行锁和本次持有的本地模型服务，后续续作重新获取锁；不维持长期阻塞进程。

### 用户选图与续作

增加新策略的选择入口：`make-video --run-dir RUN --image-selection PATH`。命令为拟定接口，实施前不会作为现有能力对外描述。
候选清单同时导出选择文件骨架，用户只需选择每个画面的候选编号；程序核对并生成接受记录。
选择文件包含 `schema_version`、`run_id`、批次、画面清单摘要、视觉设定摘要、基准绑定及逐画面的 `scene_id`、`candidate_id`、图片 SHA256，并关联整组一致性观察，防止编号跨运行误用。
选图按用户查看实际图片后作出的决定记录，不由程序伪造人工审核理由，也不将发送邮件视为接受图片。
首版要求每个画面恰好选一张；当前批次基准选择可触发其依赖的下一批图片生成，部分选择可保存草稿，但只有全部画面选择及整组一致性确认齐备才进入任何新 Wan 请求。
选择重复、缺项、不属于该运行、图片变化或清单变化均拒绝，且不启动动态生成。

接受时重新计算图片 SHA256，保存不可变接受记录，并建立从画面到动态片段及实际 Wan 输入副本的关联。
新策略以这一明确用户选择记录作为图片准入，替代旧策略要求的手写 `visual-review.json`；旧策略审核逻辑保持原契约。
已接受图片变化后不能继续消费旧视频。动态生成开始后首版不支持原地换图，需新运行；不直接覆盖旧图片或旧接受记录。

### 版本、预检和恢复

冻结 `production_strategy`、全部图片模型参数、参考图能力配置、视觉设定、基准身份、参考存储位置、画面依赖图、片段续接链、邮件收发地址、候选清单和选择记录；只保存密钥环境变量名。
SMTP/AK/SK 的具体凭证不冻结，允许轮换；模型、图片及选择身份不可随轮换改变。
旧配置缺省仍走历史策略；新配置示例显式启用 `paragraph_jimeng_v1`，旧运行不因当前默认配置变化而迁移。
新增状态与报告 schema 版本，并按版本分派读写及完成前缀验证。不能将即梦任务 ID 伪装成 Comfy prompt UUID。
新策略预检跳过 SDXL 模型及工作流要求，仍检查 Wan、超分、语音、字体、空间和媒体工具。
动态片段的多个原文绑定均可为完整有效旁白，不再套用“非主单元最多一帧语音”的旧校验。
完整原文、PCM、字幕及逐帧时间轴验证继续执行；自动技术检查不代表整片语义和发音已经验收。
新策略正式交付前额外消费确切最终候选的一致性观察，失败或 `unverified` 返回等待/返工，不产生正式交付收据。旧策略仍按其历史契约恢复。

## Tests

- 语义规划：一个画面覆盖多句；同段出现多个主题；短段落；指代跨段；完整原文和音频无遗漏。
- 时间预算：多旁白单元共同绑定画面；长画面拆动态片段但不额外出图；全部帧区间连续覆盖，无复制片段补时。
- 官方适配：签名测试向量、中文 UTF-8 请求、模型配置透传、模型参数差异、业务错误、空 data、各任务状态、多图输出及 URL 到期。
- 恢复：提交成功后中断、未收到提交响应、查询超时、下载中断，确认不会重复付费出图。
- 邮件：使用本地 SMTP 替身检查正文编号、实际附件、编码后拆包和去重；中断导致发送结果不明时不会自动重发。
- 选图：完整选择可续作，部分或过期选择不能进入 Wan；所选图到首片、父片保留末帧到续片的关联保持正确。
- 模型变更：新运行可以通过配置或 CLI 换模型，旧运行使用原模型恢复；即梦策略不依赖 SDXL 文件。
- 一致性依赖：基准未选不能生成依赖画面；同主体跨景引用同一基准；明确换装按原文记录；参考能力不明、缺配置、超数量或 URL 期限不足时在付费提交前拒绝。
- 模型能力：纯文生图模型可以生成基准；关联画面使用用户配置的参考模型；禁止自动更换模型或忽略参考图。
- 片段续接：父片未观察不能生成续片；使用实际保留末帧；额外生成帧、首帧丢弃与全片预算保持一致；父片变化使下游依赖失效。
- 视觉验收：编号选择、哈希相同、相似度分数或首尾帧截图均不能代替整组/连续视频观察；`failed/unverified` 不得正式交付。
- 历史回归：现有 make-video 恢复、视觉审核、完成前缀与交付测试；旧配置与单阶段 CLI 契约不变。
- 真实验收：本地配置官方凭证和 SMTP 授权码后，用短文案生成少量候选，确认邮箱收到、用户选图、Wan 消费确切图片、输出包含完整旁白和字幕。

## Acceptance

1. 同一重复主体跨至少三个画面，实际参考已选基准，主体身份、结构、固定属性和场景风格一致；必要的视角或剧情变化有计划依据。
2. 邮件展示基准及相关候选供整组比较；用户确认的选择与一致性结论绑定确切图像，未完成确认不请求 Wan。
3. 至少一个长画面包含两个连续动态片段，后一片的确切输入是前片保留末帧；实际连续观看无明显主体变形、动作重置或无依据场景突变。
4. 最终候选连续观看确认一致性，完整旁白、字幕和时间轴均保留；问题未解决或未核实的版本不作为正式交付。
5. 换模型、重选基准或父片变化后不会错误复用旧下游；历史运行仍能按冻结配置恢复。

## Risks

- 参考图、共享设定和尾帧续接能增强约束，但生成式模型不能承诺每次出图或视频逐帧绝对一致；本设计承诺检查、拒绝不合格版本并保留返工证据。
- 基准选图和整组观察需要分批邮件；动态续接有串行依赖及观察等待，耗时可能增加。用户不必逐句配镜头，但仍须对选图和一致性验收作出明确决定。
- 长链尾帧续接仍可能累积结构漂移；每段需要与固定基准比较，不能只与前片比较。视觉相似度或固定种子不足以证明正确。
- 参考模型及 TOS 桶、取图权限、地域和费用需在本地配置；实际服务是否可读取有限时效 URL 仍需真实联调，不能从文档推出已可用。凭证尚未配置，本轮没有官方真实调用、上传或邮件投递。
- 现有 Wan 工作流仅支持首图约束，复杂多主体、严格几何或大视角转换可能达不到验收要求；失败时保留问题并等待修改画面方案，不能自动降低一致性门槛。
- 当前未发现 `.git`，不创建新仓库；设计保存为本地文档。总体方案已确认，任务实施尚未开始。
