## Assessed obligations

- Each send still invokes the complete current `verify_global()` before deciding whether a captured Artifact needs another physical validation. Its original implementation calls ownership/source/revision checks, validates every current `guard_paths` value, checks inventories/absences/empty files, then checks model/tool stamps. No global guard or source proof was removed by this delta.
- Deduplication requires a current exact `dict` with exactly `path`, `bytes`, and `sha256`; both compared byte counts must be exact integers and both paths/digests exact strings. Equality therefore cannot silently admit a Boolean/float byte count or a changed digest/path for ordinary captured dictionaries. This is reuse of an audit from this invocation, not a cross-call cache or a path/mtime shortcut.
- `deepcopy(self.guard_paths)` preserves the original nested Artifact values. Updating a current dictionary in place to match changed file bytes does not update the send's baseline. The current binding may pass its global audit, but the different original capture then undergoes physical validation and refuses the changed file. The new test directly exercises this case using a supplement outside the original source proof.
- A removed binding is checked against the original snapshot. A binding replaced with a different identity is also checked against that snapshot. Replacing a dictionary with a fresh dictionary containing the identical typed identity remains eligible: the obligation is the same bytes, not Python object identity. A callback that adds a current dependency before the global Artifact loop causes that dependency to be audited normally. A callback that removes an original dependency leaves the independent captured obligation intact.
- Request-linked Artifacts retain their existing deep-copy capture and initial validation. Inputs/request/graph files continue to be captured physically. Any capture absent from the global set retains its separate physical check; a capture that is already an identical global obligation is checked there. Request/graph JSON semantic comparisons remain after the byte checks. The supplied mutation case exercises graph bytes; it does not separately test every request/input variant.
- Continuity callbacks run before the global Artifact loop in the inspected implementation. Their changes therefore precede the audit reused here. The prior coverage callback-disqualification repair remains unchanged and is not re-reviewed. The send deadline checks still surround the complete returned guard at its transaction call site.

The reuse has an explicit timing boundary: it establishes that an identical current binding was checked during the completed global audit. It does not establish an atomic snapshot of every file through network transmission. A physical file changed after its last validation can still race a send; the old second scan also had a final-read race. Removing the second scan intentionally moves the last check of duplicated Artifacts into the global audit. I found no ordinary callback after that Artifact audit which changes those bindings in the original global implementation. An arbitrary replacement of `verify_global()` or `verify_captured_bytes()` that omits checks, or a custom wrapper that removes a binding during its audit and restores it afterward, invalidates the reuse premise; this review does not certify such replacements. The new code does not independently authenticate those methods. If such wrappers become supported behavior, their audit contract must be established or deduplication disabled for them.

## Remaining-cost calibration recommendation

Do not rerun the approximately 1,111-second unchanged semantic context solely to estimate this small delta. Preserve profile `2807d59d` as the observed baseline for the unchanged source, ownership, writer, captured, and global methods. It did **not** measure capture construction or the returned capture guard itself. The failed control's `capture_extra` is an inferred charge, not a measured duration of those methods; subtracting it without replacement would not be defensible.

Use a narrowly isolated, explicitly fixture-only calibration of the **current real capture implementation**, separating (1) construction, including the 270-entry deep copy and request-linked/file captures, from (2) each returned guard's work outside `verify_global()`. A controlled global stand-in can isolate the latter because the model separately charges the unchanged observed global cost. Such a stand-in supplies timing isolation only, never admission evidence. Populate ordinary Artifact dictionaries at the actual cardinality and representative path lengths, and exercise all remaining physical reads with real production-sized inputs/request/graph and request-only Artifact files in disposable diagnostic storage. Prefer exact available saved request data; when unavailable, document a conservative upper-size/count envelope. Include valid metadata equality, JSON parsing/comparison, and the request-only Artifact hash costs; a tiny five-test fixture alone does not bound them.

Record implementation/fixture identities, file sizes/counts, repeated elapsed samples, and a conservative maximum plus explicit margin. Charge construction once and the residual on every actual returned-guard invocation, while retaining all existing global/source/model/tool charges without double counting. Keep changed/missing binding cases as refusal/fallback tests, not an assumed fast production path. A useful check is whether the chosen residual allowance still fits after the actual 13 guard calls and all constructor calls are counted. A passing revised model is conditional on its measured data envelope, baseline costs and cold allowance; it is not a real GPU/service deadline guarantee. No calibrator was implemented or run by this review.
