# TTS-VOX-10 安装迁移及默认切换

来源：用户明确请求完成 TTS-VOX-10；任务定义为 `docs/voxcpm2-integration-design.md` §9。

沿用现有 Windows 安装与迁移入口，增加独立 VoxCPM2 安装器。官方源码、模型 revision、CUDA wheel 与传递依赖使用 01 冻结版本，不启用 09 未达门槛的优化。Vox 使用独立环境；FunASR CPU 时间戳继续使用已有 GPT 工具环境，明确验证其依赖及本地 timestamp 模型。

安装器支持联网安装和离线复用、只检查、只部署不激活。已存在的环境先检查，通过则复用；未知源码版本或冲突资产拒绝覆盖。模型 SHA256 只在下载/部署验收时检查，不进入生成循环。

新安装必须提供批准音色资产目录（含 voice.json、reference.wav 和批准完整样本）；不使用公共替代参考或随机声音。仓库 `config/approved-narration.json` 是安装的冻结标准；运行根默认配方必须与其声学身份相同，旧默认配方可备份后升级。始终保持 reference-prompt、42/2/20、.95、500ms、-23dBFS、固定引导语及原文正文对齐。

显式激活只修改指定共享配置的 tts 与 tts 服务地址，先验证当前依赖及参考，再保存原始字节备份，原子写入。幂等重复不产生备份。显式回退恢复选定的同目录备份，先备份当前配置；不因 Vox 失败自动退回旧后端。历史 work、output、冻结配方与音频不修改。

迁移继续复制 shared 依赖；恢复时修复 Vox venv 基础解释器，并只重定位共享配置中的旧运行根路径（包括 Vox profile、默认配方、旧 voice 路径）；不重写历史运行。迁移后的 Vox 环境和依赖验证通过再记录 ready。旧 GPT 安装包无 Vox 配置时仍走原兼容路径。

替代方案：另建安装系统会重复下载/目录管理；取消 GPT 工具环境则需新建并验证 CPU 对齐环境，超出本任务。选择在既有入口上补齐依赖和明确激活。

验收：资产冲突/缺失、幂等激活和精确回退、重定位不触碰历史的测试；PowerShell 入口真实执行的小夹具；当前实际安装离线检查；新目录恢复的真实 Vox 环境启动；批准配方的短正文 GPU 样本与恢复无新增请求。不会据此补记 TTS-VOX-08 完整视觉验收。
