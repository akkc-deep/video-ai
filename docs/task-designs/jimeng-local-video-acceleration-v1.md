# 本地 Wan2.2 视频生成链路性能优化方案（v1）

> 状态：设计方案，尚未执行代码改造与本机 GPU 基准。**本轮 P0 优先重构重复全局校验，同时把断点恢复正确性定为强制验收标准。**适用分支：`v1`，生产策略：`paragraph_jimeng_v1`。**优化范围从“即梦图片已经人工选定”开始，到本地视频生成、超分、合成结束；即梦生图 API、候选提交/下载/选图一律不修改。** 本文件不授权恢复已暂停生产、调用付费 API。

## 1. 实际生产链路与优化目标

实际链路：文稿/配音和分镜规划 → **即梦云端图片候选** → 选图/人工确认 → **本地 ComfyUI + Wan2.2 I2V 14B 生成视频** → 技术检查、父片尾帧续接和人工连续性确认 → 原生帧超分 → 合成和交付。不要误把即梦视为视频生成云服务。

本轮仅针对**本地视频制作时间**优化：提升 **质量验收通过的本地有效视频秒数 / 从选图完成到本地成片的墙钟时间**。即梦提交、等待、下载和人工选图时间不计入本轮优化收益；原始输入、已选图片、全部视频帧、场景连续性与人工审核机制不变。

仓库现有基础：`workflows/wan22_i2v_14b_api.json` 默认 40 步、CFG 3.5、high/low 双 UNET、Euler/simple、FP8 scaled；图中另有 4 步 / CFG 1 的开关，但没有证明正确加载对应蒸馏 LoRA，**不得直接打开 4 步开关进入生产**。`src/video_ai/planning/scene_clip_continuation.py` 固定 `steps=40`，并形成片段继承关系。

## 3. P0：本地性能基线和可观测性

从**已确认的选中图片**起计时，增加不含密钥、提示词原文的结构化耗时：

| 本地阶段 | 指标 |
| --- | --- |
| Comfy 服务 | 启动、冷/热模型加载、模型卸载、峰值显存、GPU 利用率 |
| Wan I2V | 图像准备与文本编码、high/low 采样分别耗时、VAE 解码、视频编码 |
| 片段处理 | 原始视频探测、trim、末帧提取、父片接受等待（单独统计） |
| 超分 | 单帧 GPU 推理、批次吞吐、I/O 及完整证据校验 |
| 合成 | FFmpeg 编码、字幕音轨合成、交付校验 |
| 整体 | 本地每片段 P50/P95、每可用视频秒成本、失败/重做率 |

推荐 3 个新实验 fixture（低运动、高运动、父子续接），固定选中图片、prompt、seed、输出帧数与尺寸；冷启动 1 次、热运行至少 3 次。只读既有 run，真实推理只在明确允许的新实验 run 运行。输出 JSON 和 Markdown 对照报告，不把局部离线微基准外推成实际整片提速。

## 4. P0：全面精简重复校验并保证断点恢复

### 4.1 先建立校验调用台账

重点审计 `scene_clip_records.py` 中的 `verify_global`、`capture_guard`、`validate_artifact`、`validate_clip`；`production_scene_clips.py` 中生成前后和媒体检查；`production_scene_upscale.py` 的逐帧及阶段全局校验；`production_scene_composition.py` 的多层全局校验；`scene_comfy_transactions.py` 的 HTTP guard；以及 `verification.py`、`scene_revision_records.py` 等公共验证。记录每次调用的文件数、字节数、哈希/视频完整解码次数、耗时和是否具有独立拦截价值，区分正常生成与中断恢复。不得因函数名相同就假定校验可以删除。

### 4.2 校验分层，删除没有新增保护作用的重复计算

- **首次准入**：新 run 或恢复 run 第一次进入阶段时，检查冻结配置、模型/workflow 身份、所需输入与依赖闭包；既有历史产物在被信任前需证明内容真实性。
- **稳定阶段**：对已持有可靠内容身份、受原生只读/运行锁保护且未发生依赖变化的全局输入，使用作用域内的证明，不再每次重复完整读取与哈希。其他平台或不具备强保护时保留严格回退。
- **单片段操作**：只校验当前 clip 的输入、相关父片证据、当前请求与输出，而非扫描无关场景历史。
- **媒体计算**：同一事务、同一媒体字节与同一工具/规则身份的 ffprobe、SHA、解码结果可以复用；不得只依赖路径、文件大小或 mtime。
- **必要边界**：所有对外提交、持久化原始请求/结果、输出晋升和发布前保留所有权、来源身份、不可变结果、冲突与内容校验；不因性能优化跳过异常/篡改拒绝。

优先移除 `verify_global` 重复遍历、重复模型 stamp 校验、相同媒体连续两次完整探测、超分逐帧重复扫描共同依赖、合成中同一受保护来源反复完整校验。每项删除须先证明它没有独立安全收益，且不改变持久化结果格式和旧记录兼容性。

### 4.3 断点恢复绝对不能退化

保持独立的 **durable intent → 已接受 ID → 运行状态 → 已完成产物 → 最终提交** 恢复链。任何进程中断、终端关闭或重启后，所有进程内校验缓存均作废，必须从持久化记录重建可信证明。对已有媒体先验真再复用，决不能因缓存失效就重新生成已完成的视频/超分帧。未取得明确完成证据时只尝试恢复原请求；未知提交不得未经确认盲目重发。父片尾帧、人工观察接受记录及子片输入必须重新建立正确的依赖绑定。

正常生成和中断恢复分别测试：提交前、发送后但未记录 ID、任务执行中、生成成功未验收、媒体晋升前后、超分 N 帧后、最终合成中断。针对进程退出的 Wan 扩散中间步骤不承诺可恢复；只有明确持久化的 Comfy 任务/结果或可验证媒体才能复用。发生真实服务重启时须检查 Comfy 队列/history 是否仍可信，不能假定旧队列一直存在。

### 4.4 性能和正确性验收

采用调用次数 + 真实媒体墙钟基准比较优化前后；覆盖恶意替换同大小文件、改回 mtime、符号链接/文件身份变化、模型版本变化、父片内容变化、运行锁失效、重复/冲突 accepted、原始任务未知状态、断点重启、新旧格式混合。目标是尽可能取消无新增作用的验证，而不是以减少安全性换速度。未经真实实验不能承诺固定加速倍数。

## 5. P1：无画质变化的代码路径优化

### 5.1 单事务内复用视频探测

检查 `src/video_ai/runtime/production_scene_clips.py::_technical`：新生成 `generated.mp4` 时，`generated_producer` 已执行 `inspect_video`；随后 `source_producer` 为 trim 再次 `inspect_video` 同一文件。可仅在同一次媒体事务的内存变量里传递已经验证的 `source_info`，避免重复完整探测。**恢复路径**中如果 `generated_producer` 因已有合法结果而未运行，仍必须执行原来的完整 `inspect_video`。保留 trim 产物完整核验和原媒体身份校验。

回归：新生成、从 generated 成功后恢复、篡改输入、错误 frame count、进程中断、未授权修改；检验产物 SHA/帧数/时间戳/证据与原路等价。

### 5.2 服务和数据准备重叠

实测拥有所有权的 Comfy 进程是否在同一个授权生成阶段重复装载模型；同一阶段下可复用模型驻留并重叠 CPU 图像准备与 GPU 采样。不能让 worker 并行持久化不可变任务证据；所有写入仍在持锁的协调线程完成。不得跨人工审核无限期保留 GPU 服务。

### 5.3 依赖感知调度

`production_scene_clips` 中父子片段有尾帧和人工观察依赖；必须保持**同一连续链串行**。不同场景的 CPU 图像适配、图谱组装、磁盘准备允许在受控资源预算内有限预准备；单张 GPU 的 Wan 采样不盲目多任务并发，优先避免显存换入换出。绝不跳过片段依赖与人工连续性审核。

## 6. P1 实验：独立高速 Wan 推理配置

新增与原图隔离的 `wan22_i2v_14b_fast_api.json` 和 mapping/provenance，保持原 `wan22_i2v_14b_api.json` 字节不变。

按顺序、每次只引入一项变化：
1. 使用明确匹配 **Wan2.2 I2V 14B high/low 双专家** 的蒸馏/LightX2V LoRA，验证模型路径、强度、步骤数、CFG 与输出。
2. 在 Windows RTX 5090D V2 的具体 CUDA/PyTorch/Comfy 组合上验证 SageAttention，不因社区经验默认开启。
3. 再评估兼容的 TeaCache/MagCache 或其他缓存方案；必须分别核验双专家与跨帧一致性。
4. 最后评估 `torch.compile`、显存驻留和组合收益；冷启动编译成本单独记录。

配置档位：`quality` = 原 40 步基线；`fast_experimental` = 独立加速图。模型/LoRA SHA、workflow hash、节点版本、attention backend、cache、采样步数/CFG、Comfy 版本全部纳入**新任务**的冻结身份、request/graph/恢复证据。旧 pending/accepted/unknown 的生成身份绝不变更或重新 POST。

必须检测：黑帧/NaN、闪烁、角色与纹理一致性、颜色漂移、运动稳定、尾帧接缝、完整帧数/PTS、GPU 峰值显存和失败重试。质量显著下降时不得自动推广为默认。

## 7. P2：本地超分与合成优化

- 基准测量 `upscale_api.json` 中 RealESRGAN 单帧运行的模型常驻情况、每帧读写与 GPU 空闲。先验证**同一阶段复用模型与受限预取/写回队列**，不得因为并行工作者导致多个 RealESRGAN 实例争抢显存。
- 对同源、同参数、同工具身份且已完整校验的输出实施只在同运行事务生效的安全复用。已完成的批量提帧和合成重复解码优化不重做。
- 研究硬件视频编码（如 NVENC）作为**实验可选项**，必须比较视觉质量、像素/PTS/帧数/颜色元数据与现有验收契约；若与全像素一致性证明冲突，保持原 FFmpeg 路径。
- 优化流水线的峰值存储与工作重叠：只有在完整的帧证据与恢复状态仍可追溯时，才进行磁盘/显存预取；不删减生成帧或降低最终 1080P 输出要求。

## 9. 明确非目标

**不修改即梦生图链路**（提交、候选、轮询、下载、选图、通知）；不改变原始文稿/TTS、不删减内容、不降低视频帧数、不跳过连续性验收、不偷偷降低最终输出画质、不把离线局部基准外推成整片耗时。
