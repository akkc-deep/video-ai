# TTS-VOX-09 性能对照设计

任务来源：[接入设计 §8–9](../voxcpm2-integration-design.md)。用户于 2026-11-28 要求完成本任务。

目标是用当前批准配方评估可用加速，只有实测收益和音质均通过才启用。现有官方 BF16 / FP32 AudioVAE、串行模型常驻是基线；不改声音、seed=42、cfg=2、steps=20、0.95 倍语速、500ms 停顿补足、-23dBFS 全篇 RMS 与固定可丢弃引导语。既有未提交工作与历史任务不改写。

## 方案

实施选择：实验中使用官方 `build_prompt_cache` 与 `generate_with_prompt_cache`，复用同一参考的左右 padding 特征。这与当前顶层 `generate` 内部使用同一生成路径，无需更换后端、权重或依赖。缓存只存在本次模型实例中，绑定冻结参考 SHA256、参考文本、模式、模型/源码版本；不使用滚动参考，不落盘复用特征。

其他方案：Nano-vLLM / 批处理需要另行验证 Windows、Blackwell 和参考续读契约，当前锁定环境没有该实现；torch.compile / CUDA Graph 涉及额外编译工具链和动态图兼容，当前 optimize=false，暂不安装或更改环境。不能将这些筛选结论写成实测失败。

## 实验与输出

独立入口 `scripts/experiments/voxcpm2_performance.py`，专用 VoxCPM2 Python，运行根沿用 VideoStorage；所有音频与逐次结果写入新的 `scratch/benchmarks/TTS-VOX-09/<timestamp>`。冻结当前默认配方、参考 WAV 和部署规格一次，不重新哈希模型权重。

三个文案取已批准旅行者2号旁白的首、中、尾：长段、短段、极短尾句。固定引导语只用于合成；交付 WAV 经 atempo 后按现有声学静音分隔去掉引导语，按原文正文采样点报告时长，不做 ASR 或强制对齐。使用现有 assemble_narration 补足 500ms 停顿并统一到 -23dBFS。不声称新的句级字幕或完整视频验收。

先单独记录导入、模型加载、首次生成，再构建缓存。热基准两轮，逐文案 AB / BA 交替，禁止重试美化结果。记录每次生成耗时、含写盘及后处理耗时、原始/正文秒数、RTF、峰值 allocated/reserved 显存、失败与重试计数。冷样本不进入热均值。汇总按总生成时间/总实际音频时长计算 RTF，含引导语与正文 RTF 分列；缓存一次性构建成本单列。

收益门槛是热生成耗时至少减少 10%，两轮均为正收益；PCM16 必须所有配对一致，失败/缺项不能判通过。即使这些客观条件通过，未有用户对照试听则保留当前官方生产路径，候选仅留实验；不得冒充主观音质达标。0.3 RTF 目标是否达到如实报告。

## 验收

有可复现命令、真实 CUDA 对照结果与可试听正文样本；汇总有防止缺项、顺序错配、音频差异和冷样本污染的测试。报告明确启用决定、适用范围与未验证项；在接入设计中登记 09 的评估结果，不自动启动 10。本任务允许加速未达门槛而保留官方后端。
