# 通用起始图质量优化方案

日期：2026-10-14。状态：方案草案，未实现、未运行新生成实验。已补充静态 LoRA 与提示词质量控制设计。

## Goal

提高程序在不同文案、题材下生成的起始图质量，让进入 Wan 的图片本身具备正确内容、自然质感、清楚构图和适合运动的初始状态。通过真实起始图及短视频比较确认收益，避免按单条视频添加专用修补。

用户已明确：先只做方案，不实现；方案必须通用。用户提出起始图质量过低的判断，现有样本支持优先调查起始图，但尚未证明提示词、模型或分辨率分别造成多少影响。

## Scope

包含：起始图提示词及其质量控制、静态生成模型/可选 LoRA 与采样方案的对照选择、图生视频所需的初始状态、有限候选与选择策略、跨题材验证，以及未来接入现有流程的边界。

本轮仅写方案。未来第一阶段也只评估起始图；对少量选定图片生成短视频，检查收益是否能传递到下游。

不将配音、字幕、背景音乐、转场、帧率和超分列为本次优化对象。不修改历史运行、历史证据或已有交付。模型下载、依赖安装、服务启动和新媒体生成均未在本轮执行。

### 2. 先定义“好起始图”

按五个维度评价，不用分辨率或锐度替代总体质量：

1. 内容准确：主体、数量、关系、场景及原文明确的特征正确。
2. 视觉自然：没有明显条纹、色块、错肢、塑料感、不合理光影或重复结构。
3. 构图清楚：主体可辨认，有合理景别、尺度、遮挡关系和活动空间。
4. 动作可开始：静态图展示接下来动作的开始状态；图像中的状态与动作描述相容。
5. 连续性：相邻镜头中的同一主体和同一场景没有无依据的外观变化。

内容准确和严重伪影属于否决项；清晰度、光影和构图作为优选项。不得因图片漂亮而接受错主体或错数量。

### 3. 三条技术路线

| 路线 | 做法 | 价值与限制 |
| --- | --- | --- |
| A：改好现有 SDXL 输入 | 以已有英文 1280×720 路径为新基线，完善构图、光照、实体特征和初始状态，受控比较采样参数 | 无需新模型即可验证；基础模型的表达能力仍可能不足 |
| B：升级静态模型 | 使用同一测试集，比较当前 SDXL 基础模型与适合写实静态图的 SDXL 微调 checkpoint | 有望改善质感和结构；具体模型、许可、体积、兼容性与效果待评估 |
| C：更换静态生成体系 | 若 A/B 未达标准，再评估其他本地图像模型或在线服务 | 可能改善语义理解和复杂结构；会涉及新的工作流、资源或费用条件 |

推荐顺序为 A → B，C 作为后续选项。最终由跨题材实测选择路线，不提前认定“换模型必然有效”。第一轮直接使用已有模型，不进行未经评估的下载或安装。

### 3.1. 可选静态 LoRA

将 LoRA 纳入路线 A/B 的可选实验项，不将其作为默认必需组件。优先评估作用于自然质感、光影或材质的候选；主体专用 LoRA 只作为按明确需求选择的能力，不能在通用流程里按专名自动绑定。

当前 SDXL 工作流没有 LoRA 节点，`D:/VideoSi/models/comfyui/loras/` 只有占位文件，配置的固定 `MODEL_FIELDS` 也没有静态 LoRA 字段。因此它是待设计的可选扩展，不能称为已支持或已安装。

ComfyUI 接入建议：在 `CheckpointLoaderSimple` 与采样/文本编码之间加入 `LoraLoader`；其 MODEL 输出送往 KSampler，CLIP 输出送往正、负文本编码器，VAE 沿用 checkpoint 输出。无 LoRA 时绕过加载节点，沿用原图。具体文件、加载器类型和连接需与所选 LoRA 相符，未来新增独立版本模板和 mapping，不修改旧模板。

兼容性必须明确记录：基础架构、适用 checkpoint、文件身份、许可、触发词、`strength_model`、`strength_clip`、推荐采样参数。SDXL LoRA 不可直接替代 SD1.5、FLUX 或 Wan 的 LoRA。即使架构相同，对某个 checkpoint 有效也不保证对另一个微调 checkpoint 有效。

第一轮只比较“无 LoRA”与“单个 LoRA”，不堆叠多个。强度按照该 LoRA 的说明选取少量实验档位；若没有说明，可提出 0.3/0.6/0.9 的 model 强度实验网格，但不能直接当成生产推荐值，CLIP 强度须单独记录。固定提示词、种子、尺寸和采样参数后比较；若 LoRA 明确要求特殊 steps/CFG，则将完整配套预设另列方案，不能把参数影响全部归功于 LoRA。

加速/蒸馏类 LoRA 与画质/风格类 LoRA 分开评价：前者主要改变推理成本和参数要求，不能凭名称或步数少推断画质提升。本方案优先研究静态画质，不顺带启用 Wan 的加速 LoRA。

LoRA 的触发词由已验证的预设统一注入，不让规划模型自行编造加载名和强度；最终含触发词的完整提示词仍要参加语义和冲突检查。同一连续场景使用同一预设，不能每镜头随机切换风格。无收益、内容失真或留出题材退化时保留无 LoRA 方案。

### 4. 通用提示词与起始状态设计

原文、事实、实体 ID 作为规划证据保存。发送给静态模型的内容按“可见主体及必要特征 → 场景 → 景别/构图 → 合理光照/材质 → 起始状态”组织，不发送字段标签和事实锚点。

主体外观从原文和实体目录提取；同一实体复用同一份外观约束，不在代码中按视频标题、专名或镜头编号添加补丁。没有外观依据时不得擅自添加会改变语义的结构。

抽象旁白延续有依据的场景；禁止将信息、时间、信件等抽象概念自动变成文字、图表或无关实物。光照和风格服从场景及用户原文，不能为所有题材固定同一套金色或电影特效。

静态与动态描述共用动作计划：起始图描述动作开始时的姿态，视频描述从该姿态到目标状态的变化。即使原文未要求同一具体拍摄地点，也应尽量保持同一场景段落的环境连续；不得为了连续性覆盖原文明示的换景。

提示词长短由模型编码预算和实际效果决定；避免简单扩充到大量形容词，也不将所有视觉字段统一截成同一长度而丢失关键条件。

### 4.1. 提示词质量控制

目标是减少并发现错误，不能承诺生成式提示词或扩散图片百分之百正确。把“格式符合规则”“原文语义一致”“实际画面正确”作为三种不同结果记录，不互相代替。

流程：原文与上下文 → 有出处的视觉事实及初始/结束状态 → 模型适用的提示词编译 → 确定性检查 → 独立语义复核 → 起始图生成与观察。任何自动提取的事实也要对照原文，避免把错误提取结果冻结后当成唯一真相。

| 层次 | 检查内容 | 可证明的边界 |
| --- | --- | --- |
| 结构与编译 | 原文引用和实体引用有效；允许的字段、枚举、版本符合契约；最终模型提示词没有证据标签、未替换占位符或重复主体段落 | 能证明结构和编译规则符合约束，不能证明描述理解正确 |
| 事实覆盖 | 对照原文核对主体、数量、否定、属性、空间关系、时间顺序、代词来源；关键约束须能指向对应原文范围 | 可发现明确的遗漏/矛盾，不能靠英文关键词出现就断言画面语义完整 |
| 提示词冲突 | 初始状态与动作相容；光照/风格服从场景；正负提示词不同时要求和排斥原文主体或必要元素；加入 LoRA 触发词后重新检查 | 规则只能处理有定义的冲突，不能穷举所有物理或语言歧义 |
| 编码预算 | 按真实文本编码器 tokenizer 检查最终文本及分块情况；必要主体与关系优先，删减重复风格词；记录编码预算诊断 | 英文、字符数合格都不等于模型有效接收了全部语义；不把 CLIP 的单块长度误当所有工作流统一总上限 |
| 独立语义复核 | 复核者只读取原文上下文、初始/结束状态和最终正负提示词，输出遗漏、冲突、无依据新增项及原文依据，不读取生成者的自我解释 | 独立请求有助于发现错误，同一语言模型仍可能共享错误；复核通过仅是文本结论 |
| 实际画面 | 将生成 PNG 与原文及动作计划比较，并检查条纹、结构畸变、错数量、主体外观和背景连续性 | 最终判断提示词与模型组合是否有效的必要证据；文本检查不能替代 |

事实描述与美术建议分开保存：原文未限定的景别、光线可作规划建议，但不能添加改变故事的主体、事件、结构或数量。多主体或群体场景保留原文数量关系，不能套用“每张图只能有一个对象”的规则。

不全局禁止所有文字、标识和多物体：原文明确需要这些元素时，负面提示词须调整。反之，没有依据时不诱导生成文字或图表。反向翻译和图文相似度只能作辅助诊断，不能作为语义通过的唯一条件。

文本修正最多一次，保留修正前后及具体问题。仍存在矛盾或无法明确描绘时记录 unresolved，不生成“保证正确”的结论，也不为了继续生产擅自改变原文。该结果如何与现有自动入口衔接，在实施前明确；本轮不新增人工批准流程。

复核格式建议固定为问题数组，每项包含 `kind`（omission/contradiction/unsupported/ambiguous）、`source_range`、`prompt_fragment`、`reason`。问题范围不得靠模型自行指定新的原文事实；应用校验范围合法性。文本质量记录、图片选择记录和生成请求分别保存，便于判断是提示词失败还是模型表达失败。

### 5. 分辨率与采样比较

采用已有 1280×720 作为 SDXL 新基线，约 92 万像素。为判断历史低分辨率的影响，可在相同模型、提示词和种子下额外比较 768×432 与 1280×720。

分辨率、提示词、模型、steps 和 CFG 分别比较，一次只变一个因素。保留现有 25 steps / CFG 7 / dpmpp_2m / karras 为参数基线；候选参数由选定模型的要求和实测确定，不在本方案中将某个新数值写成已验证最佳值。

检查原始 PNG，也检查 Wan 将图片适配到 768×432 后的画面，防止大图细节在实际视频输入中丢失。静态放大或锐化不作为新增真实细节的证据。

### 6. 候选图与有限修正

建议生产策略为每镜头先生成 2 张独立种子候选；若均有严重问题，最多追加 1 张针对问题修正的候选。总数不超过 3，不进行无限重试。具体默认数量须根据实测耗时和质量收益最终确定。

选择顺序：先排除内容错误或严重伪影，再比较自然度、构图和清晰度。保留所有候选、种子、提示词、模型和选择理由；图片选择后固定其身份再送入 Wan。

自动选择能力尚未确认。正式方案必须在“视觉模型评分”与“确定性技术检查加人工实验评价”之间明确边界：技术检查只能证明文件、尺寸、解码等事实；锐度和图文相似度不能单独证明正确外观。视觉模型只能在跨题材评价可靠后接入自动选择。不得为自动化方便把未核实写成质量通过，也不以本方案新增人工逐镜审批流程。

### 7. 接入与恢复边界

未来以版本化的起始图策略接入 `image_parameters` 和 `produce_start_images`，记录实际采用的提示词版本、模型、工作流版本、采样参数、种子及被选择图片。起始图与视频共用同一主体和动作定义。

现有 `validate_fixed_visual_template` 会拒绝采样参数及节点变化。未来若比较参数或接入新工作流，需要增加明确的版本化模板，不能直接修改固定基线后让旧运行依赖新参数恢复。

历史运行继续消费其保存的原始请求和配置；新策略只作用于新运行。旧英文模式与旧中文模式都应保留可恢复性，不能在恢复途中替换图片或重新发送未知生成请求。

### 实际视觉实验（未来进行，本轮未运行）

建立固定跨题材测试集：人物、自然/动物、产品/机械、建筑/室内、科学/太空，每类 2 个场景，其中一个包含动作，共 10 个场景。每方案每场景 3 个种子，共 30 张起始图；至少包含静态细节、复杂结构和抽象旁白场景。

先比较已有英文 1280×720 路径与通用提示词方案，固定模型与种子；再对入选提示词比较静态模型或采样参数。另留未参与提示词调试的文案作为留出测试集。所有图片使用匿名方案编号混排评价，不以单张最佳图作结论。

LoRA 实验单列：对同一 checkpoint 和入选提示词比较禁用、一个 LoRA 的少量强度档位，沿用同一测试集和种子。逐类检查收益与退化，并确认触发词没有改变原文内容。LoRA 若只改善一个题材，不称为默认通用增强。

记录严重伪影率、内容正确率、五个评价维度、每镜头候选数及实际耗时。对有动作的 5 个场景，各采用基线与入选方案的选定图片生成同长度、同参数、同种子的短视频，检查伪影是否继承、主体几何是否保持、动作能否从起始状态发生。

现有预览命令会实际启动服务并生成媒体，不在本轮执行。跨题材实验入口和确切命令尚未存在，应在进入实施前补全；不得将上述实验设计写成已测试结果。

## Acceptance

本轮方案交付：文档保存，证据、建议和待决事项分开；未修改产品代码、配置、工作流，未生成新媒体。

未来建议的验收标准，待用户评审确定：

1. 固定测试集和留出测试集都覆盖不同题材，测试文案没有专用代码分支。
2. 新方案内容正确率不低于基线；严重伪影图片占比不高于 10%，且基线高于 10% 时至少下降一半。以原始候选及最终选中图片分别统计，禁止只报告选图后的指标。
3. 五类题材中至少四类的选中图总体评价优于基线，剩余类别没有内容准确性的明显退化；展示全部图片及逐图理由。
4. 至少 4/5 个动作场景的短视频能从设定初始状态开始，且没有继承被发现的严重起始图伪影。
5. 记录静态生成和选图的实际耗时、资源及费用。允许的增加上限仍待决定，不预先编造性能承诺。
6. 相关代码测试退出码为 0；旧运行、已有交付和原始请求保持可恢复且不被覆盖。
7. 如采用 LoRA，选择依据包含无 LoRA 对照和留出题材；运行记录可还原具体 checkpoint、LoRA、触发词及两种强度，禁用时可回到对应无 LoRA 流程。
8. 提示词质量记录能分别说明结构/语义/画面三层状态。没有观图证据时不得宣称画面正确；含已知矛盾的文本不能仅因格式正确而通过。

## Risks

- 起始图问题已经实际观察到，但没有受控实验，不能将条纹等缺陷全部归因于中文提示词或低分辨率。
- 已有英文 1280×720 模式的真实质量尚未确认，应该先测试，避免重复设计已经存在的改进。
- 新静态模型的具体名称、许可、下载来源、兼容性和硬件适配尚未确定。是否允许在线服务也未确定，路线 C 只作备选。
- LoRA 的具体文件、适用 checkpoint、触发词与强度尚未确定；风格偏置可能牺牲科学/机械结构或其他题材的真实性，必须用无 LoRA 对照及留出场景检查。
- 语义复核模型、tokenizer 访问方式和 unresolved 与自动入口的衔接尚未确定；同模型自检、反向翻译或格式约束不能构成语义保证。
- 自动视觉判别器尚未选定；不能把未来候选选择能力视为已经具备。
- 每镜头 2～3 张候选和跨题材实验的成本可能较高；可接受的耗时、显存和费用上限待定。
- 用户没有指定新的审美风格；方案优先保留文案已有风格要求，通用默认风格需在样片评价时确认。
- Wan 的低分辨率输入、运动生成或后续超分仍可能造成新的缺陷。起始图改善只证明解决上游质量问题，不保证成片全部问题消失。

尚未确定的模型、预算、自动选择方式和实验入口意味着本文是可评审方案，不是已经获准实施的完整合同。
