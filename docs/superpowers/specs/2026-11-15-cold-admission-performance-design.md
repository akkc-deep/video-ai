# Cold admission performance

The user requested comprehensive optimization after revision10 spent more than five hours preparing inherited sources without new inference. This extends the prior authorized inline optimization; design and implementation details remain delegated. AGENTS.md requires avoiding excessive validation during video production.

## Outcome

Cold loading, source-clip context construction, progress reconstruction and resume must stop multiplying physical proof work by nested capture count. Preserve the existing media, source identities, accepted/rejected observations, parent gates and GET-only recovery of unknown submissions. Resume the original video after the optimized read path is measured.

## Approach

Chosen engineering approach: separate physical verification from propagation of already captured dependencies. Use bounded synchronous read passes under existing native input protection, with fresh boundary verification. Check unique files and shared directories rather than repeating an ancestor walk at every lookup. Replay immutable proof rows as data, retaining conflict/capacity/failure handling. Semantic memo keys must include effective source image and clip scopes.

Alternatives considered: merely adding more semantic caches leaves native metadata amplification; retaining a whole mutable context or extending artifact batches over model calls/writes risks stale progress, inventories and parent state. Neither is the primary fix. Immutable source value reuse can be extended only if measurement still identifies reconstruction as material after physical duplication is removed.

## Boundaries

- Work against the current dirty checkout, preserving its exact source snapshot at `.tools/cold-admission-optimization-baseline-20261115-011834`; do not reset or commit unrelated changes.
- A reusable physical pass is active only on its owning thread and live native window, during a synchronous read. Writer promotion, explicit checkpoints and scope/window closure invalidate it. Checkpoint transactions that enclose network/persistence do not inherit a long physical reuse period.
- Files retain complete baseline, native entry identity and ownership. Directory handles do not freeze reparse attributes: fresh boundary checks and strict scanning of arbitrary/lazy inputs remain required.
- Ordinary observe functions remain strict. Trusted replay only merges a successfully admitted ByteGuard's existing rows; it performs no new filesystem interpretation.
- A cold RevisionGuard grows while imports are admitted. Cache individual dependencies or a dependency-versioned proof, never an unversioned whole guard during construction.
- Source scopes distinguish full-content admission from declaration-only siblings. Scope tightening, competing owned evidence, newly appearing absence/inventory entries, typed input changes and parent changes must remain detectable.
- No new dependencies, model requests, rendering or repeated media review for development benchmarks.

## Evidence

Use focused RED/GREEN cases and a real Windows native-handle fixture. Measure fresh cold loading through load_prepared_inputs, clip context and progress, including exit checks. Compare the same saved source baseline and protection mode in independent processes. The prior small warm-review fixture is not completion evidence for this change. A bounded read-only probe of the existing Voyager run must complete and report stage times before generation resumes; an incomplete probe is not a successful result.
