# 旅行者 2 号审核准备性能修复记录（2026-11-11）

范围：仅素材读取、审核准备与审核批量入口；没有运行生成、放大或合成。没有新增正式审核通过记录。

## 定位与修改

- 继承来源追溯逐场景重新 load_frozen_inputs，并直接解析时间线。改用修订证明已经保存的 source_frozen，以及已有 origin_timeline 批次缓存。
- 相同来源的 common 和 load_committed_plan 反复重建。现在在本地 artifact batch 内复用来源计划，访问前后保留修订证明检查。
- 实际只读栈采样进一步定位到 _prior → _load_accepted → _expected_batch → _candidates：每次来源验证重建先前接受的图片批次。现在按来源对象、Bible、计划和批次索引缓存，保存完整 ByteGuard；命中验证原始字节/目录/缺失路径，并向外层捕获器重放依赖，批次退出再次验证。返回深拷贝，缓存不跨批次。
- 新增 consume_scene_clip_observations：多个真实观察共用一次 scene_context，逐条沿用原审核校验和落盘逻辑，失败即停止；不调用生成流水线。单条 API 保持原调用方式。
- scripts/submit_scene_clip_reviews.py 是仅提交已有审核 JSON 的独立入口，本次未运行实际提交。

## 测量口径与已知结果

scripts/benchmark_review_loading.py 使用相同 08 版素材，只读加载和 scene_context，不接触生成入口。--baseline 仅还原 Git HEAD 中原 verify_reference_provenance；其余边界一致。封存读取窗口只用于诊断读取，生产目录写入和网络连接被禁止。原始数据保存在 .tools/clip-review/ 下。

- 用户交接：原运行约六分钟后中止，首条审核未提交，不能作为成功总耗时。
- 同条件基线 performance-baseline-sealed.json：冻结输入 11.604 秒；准备输入在总测量 180 秒截止时未完成（该阶段 168.928 秒为中止耗时）。计数：来源追溯 112 次、时间线验证 24 次。退出检查后总计 291.598 秒，不是成功耗时。
- 真实 01 版时间线局部实验：三次完整解析 0.146 秒；批次缓存 0.058 秒。这只说明局部收益，不能当作完整提交提速。
- 初期全函数性能钩子与未封存输入测量包含明显诊断开销，不作为正常运行速度；部分中间测量被终止，不能视为完成。

相关测试 128 项通过（重复解析、来源计划复用、素材变化拒绝、批量审核停止语义、现有审核逻辑与修订保护）。只提交脚本 --help 成功。正式审核落盘耗时未测量，因为本次选择只读准备，不制造任何审核记录。

## 最终实测结果与局限

最终实现实测：`performance-final-batched.json`，状态 `completed`；完整完成一次只读审核提交准备及退出检查，没有写入正式审核记录。

| 阶段 | 中间完整参照（来源输入/计划已复用，尚未完成本轮其余优化） | 最终实现 |
| --- | ---: | ---: |
| 冻结输入加载 | 11.596 秒 | 11.605 秒 |

完整准备总计减少约 33.1%，场景审核上下文阶段减少约 64.6%，来源追溯调用次数减少约 51.4%。以上比较是两次**成功完成**的中间参照与最终实现，不是原始未修改版本的成功耗时；原始版本只取得了超时中止结果，不能声称完整提速倍数。最终冷准备仍需约 6 分 18 秒，输入准备阶段比中间参照更慢，因此不能宣称“首条审核等待缓慢已经彻底解决”。本次确认消除了重复构建并改善批量提交准备；冷启动仍有明显成本，需要后续继续定位。没有测量正式审核验证/落盘耗时，也没有实际运行多条审核提交，不能把只读准备耗时冒充正式提交耗时。

图片批次缓存最终采用**首次捕获、命中重放依赖、批次退出统一验证**，不是每次命中再完整验证。仅使用已经持有的原生保护句柄来加速退出检查，无法取得保护的文件保留严格检查。

读取事务内同一 guard 与同一捕获器复用本轮检查；不同捕获器仍进行首次检查，事务退出刷新检查。读取边界使用全新 artifact batch，多个重叠证明共享本轮新读取，不复用先前边界结果。新增测试先验证重复读取存在，再验证复用及变化拒绝行为。

最终验证：170 项相关测试通过；没有为性能数字反复运行全套项目测试。多轮中间只读诊断因测量边界问题或实现被替换而中止，只终止本次已知诊断进程，没有按进程名批量终止，也没有操作交接中的旧 PID。中止诊断不计作成功准备。
